## 一、为什么学习这些能力？

学习技术不只是记住命令，还包括遇到陌生问题时寻找资料、判断适用条件、验证结论和向他人提供足够信息。

刚进入实验室时，你可能遇到安装失败、示例跑不通、输出不一致。这些问题并不都需要老师直接给答案，也不应在没有方向时无限尝试。

目标是形成一条可执行的流程：

```text
明确问题 → 收集证据 → 检索与读文档 → 小范围验证
→ 需要时提问 → 记录原因和解决方式
```

## 二、先把问题描述清楚

### 2.1 区分目标、现象与猜测

| 内容 | 示例 |
|---|---|
| 目标 | 读取 data/input.txt 并统计非空行 |
| 现象 | 执行后出现 FileNotFoundError |
| 证据 | 错误原文、运行命令、当前目录、文件结构 |
| 猜测 | 程序可能从错误工作目录查找文件 |

“Python 坏了”通常只是猜测，不足以定位问题。先写出原本预期看到什么、实际看到什么。

### 2.2 保存错误原文

优先复制可搜索的文字，保留异常名称、关键文件位置和相关回溯。不只发被截断的红色截图。

截图适合说明界面位置和视觉异常，文字适合检索命令、路径和错误。涉及账号、令牌或私人目录时，保留诊断结构并进行必要脱敏。

## 三、收集最小环境信息

常见检查命令：

```bash
python --version
python -c "import sys; print(sys.executable)"
python -c "from pathlib import Path; print(Path.cwd())"
```

还可以记录：操作系统、芯片架构、依赖版本、代码提交、输入样例和最近变更。

不需要一开始倾倒全部日志和配置。信息应围绕问题，必要时逐步补充。

### 一个简短记录

```text
系统：Ubuntu，具体版本见项目环境记录
Python：实际检查到的版本
运行位置：项目上一级目录
命令：python path-demo/main.py
预期：输出非空行数 3
实际：FileNotFoundError，找不到 data/input.txt
```

版本等未知项标注待确认，不编造环境信息。

## 四、怎样构造检索词

### 4.1 从错误类型和操作对象开始

```text
Python FileNotFoundError relative path working directory
Python pathlib __file__ current directory
OpenCV imread returns None path
conda PackagesNotFoundError platform channel
```

保留库名、函数名和异常名称，去掉用户名、私人路径和随机编号等无关内容。

### 4.2 逐步缩小范围

| 方法 | 用途 |
|---|---|
| 保留错误英文原文 | 更容易匹配原始问题与文档 |
| 加库名、函数名、系统 | 排除同名但无关的问题 |
| 加主要版本 | 缩小到对应行为；精确到补丁版可能反而漏结果 |
| 搜索引擎支持时用引号 | 尝试匹配关键短语 |
| 搜索引擎支持时用 `site:` | 优先定位官方域名 |

例如：

```text
site:docs.python.org pathlib relative path
site:docs.opencv.org imread
```

搜索结果少时可以放宽版本和长句，搜索结果多时再加入约束。不要反复只搜“运行不了”。

## 五、怎样判断资料是否可靠

### 5.1 优先看什么？

1. 当前版本的官方教程、API 参考和发布说明。
2. 项目维护者的仓库说明、Issue 与已合并修改。
3. 有清晰环境、示例和验证过程的技术文章。
4. 论坛或问答中的经验，作为待验证线索。

这不是“非官方内容都不能用”。关键是区分文档约定、维护者说明和个别人环境下的经验。

### 5.2 检查适用条件

| 检查项 | 为什么重要 |
|---|---|
| 软件与版本 | API 名称和返回值可能改变 |
| 操作系统、架构 | 路径、包和二进制兼容不同 |
| 输入类型与范围 | 同一函数不一定接受所有类型 |
| 是否真的解释原因 | 只贴命令可能掩盖错误环境 |
| 运行结果与限制 | 便于判断能否迁移到自己项目 |

文章新不代表一定正确，旧文也不一定失效。以具体行为与验证为依据。

## 六、官方文档应该怎样读

### 6.1 区分文档类型

| 类型 | 主要回答 |
|---|---|
| Quickstart / Tutorial | 怎样先完成一个小任务 |
| How-to | 怎样完成某类具体操作 |
| API Reference | 参数、返回值、异常、约束是什么 |
| Release Notes | 某版本改变了什么 |
| FAQ / Troubleshooting | 已知问题怎样检查 |

初次接触先看最小教程；函数报错时再查参考，不必从首页逐页通读。

### 6.2 读懂函数签名

以 `Path.read_text()` 为例，重点关注：

- 它是对什么对象调用的方法？
- `encoding` 参数有什么作用？
- 返回字符串还是字节？
- 文件不存在、编码不一致时可能出现什么异常？
- 当前 Python 版本支持哪些参数？

示例：

```python
from pathlib import Path

path = Path("sample.txt")
path.write_text("Hello\n", encoding="utf-8")
text = path.read_text(encoding="utf-8")
print(type(text).__name__)
```

输出 `str`。示例会覆盖同名文件，应在独立目录运行。复制 API 示例前先弄清楚它读写什么。

### 6.3 不把占位符原样执行

文档中的 `YOUR-USERNAME`、`路径`、`<filename>` 等常是需要替换的说明。`[可选项]` 往往表示可选参数，不表示要输入方括号。

区分可执行代码、格式示意和预期输出；缺少文件或变量的片段可能不是完整程序。

## 七、建立最小可复现示例

### 7.1 什么是最小复现？

用尽可能少的代码、依赖、输入和步骤，仍然触发同一个问题。最小不是越短越好，关键是完整、可运行、问题不变。

### 7.2 缩小步骤

1. 保存原始状态或创建练习副本。
2. 固定一个输入，重复确认现象。
3. 移除与问题无关的界面、网络、文件和模块。
4. 用小型样例替换大数据，保留触发条件。
5. 每次简化后重新运行，确认还是同一个问题。

如果简化后问题消失，记录是哪一步改变了行为，这是有价值的线索。

### 7.3 一次改变一个主要因素

同时升级 Python、换源、重装库和改代码，即使问题消失，也难知道原因。优先在独立环境小范围验证，保留每次尝试的结果。

不要求所有情况下只能改一个字符；目标是让证据可解释，而不是机械执行规则。

## 八、怎样提出有效问题

### 8.1 标题

```text
不清楚：救命，程序完全运行不了
更明确：从项目上级目录启动 main.py 时找不到相对路径输入文件
```

### 8.2 提问模板

```markdown
## 目标

我想完成什么？

## 环境与版本

系统、解释器、关键依赖和代码版本。

## 最小复现

必要文件、输入、运行位置和完整命令。

## 预期结果

原本应该发生什么，依据是什么？

## 实际结果

关键错误原文或实际输出。

## 已尝试的方法

每个方法做了什么、结果怎样。

## 希望获得的帮助

当前需要确认哪个判断，或卡在哪一步？
```

### 8.3 请求帮助的时机

先做基础检查并简要检索。如果已重复同类尝试却没有新证据、任务接口不明确、涉及共享资源或可能覆盖数据，应及时说明阻塞。

不把“自主学习”理解为必须独自耗到截止时间。向队长提问时，一并给出已经完成的部分和下一步判断，便于对方接续。

## 九、合理使用 AI 辅助检索

可以让 AI 解释错误、列出排查顺序、帮助缩小示例或翻译文档，但它生成的链接、API 和版本信息需要核对。

### 一个提问示例

```text
我在 Ubuntu 上用 Python 运行文件读取脚本。
从项目目录运行成功，从上级目录运行失败。
下面是目录结构、运行命令、最小代码和错误原文。
请先解释相对路径的参照位置，再给出可验证的排查步骤。
涉及 API 时请提供对应官方文档。
```

把 AI 建议转化为“假设—验证—结果”。不要直接执行不理解的删除、权限、下载运行或凭据相关命令，也不要把不应公开的数据当作排查素材。

## 十、一个综合示例：定位文件路径问题

### 10.1 准备复现

```text
search-demo/
├── main.py
└── data/
    └── input.txt
```

`input.txt` 中写入 `Hello`，`main.py` 内容如下：

```python
from pathlib import Path

print(Path("data/input.txt").read_text(encoding="utf-8"))
```

在项目目录执行 `python main.py`，应成功。从上级目录执行 `python search-demo/main.py`，可能出现预期的文件路径错误；确保上级目录没有碰巧存在同名 `data/input.txt`。

### 10.2 收集与检索

记录两个运行命令，分别查看 `Path.cwd()`。用“Python pathlib relative path working directory”定位官方说明，确认相对路径的含义。

### 10.3 验证假设

如果目标是读取与脚本一起交付的固定样例，修改为：

```python
from pathlib import Path

base_dir = Path(__file__).resolve().parent
input_path = base_dir / "data" / "input.txt"
print(input_path.read_text(encoding="utf-8"))
```

从两个目录重新运行。如果目标是用户指定输入，则也可以设计命令行参数，不应把所有路径问题都统一改成相对脚本。

### 10.4 记录结论

```text
现象：从上级目录启动时报找不到 data/input.txt。
原因：原程序按当前工作目录解释相对路径。
依据：两种启动方式的 cwd 不同；固定输入路径后结果一致。
修改：固定样例相对脚本定位。
验证：项目目录与上级目录均输出 Hello。
限制：该约定适合随代码交付的样例，不适用于所有用户输入。
```

## 十一、常见问题排查

| 情况 | 改进方法 |
|---|---|
| 搜不到结果 | 提取异常名、函数名，去掉私人路径与过长句子 |
| 搜到太多无关结果 | 加系统、库名和主要版本 |
| 找到教程但复制失败 | 检查版本、前置文件、环境和占位符 |
| 资料结论互相矛盾 | 核对各自适用条件，定位原始来源并小样例验证 |
| 对方无法复现 | 补齐输入、运行位置、命令与依赖 |
| 问题被说“不清楚” | 把目标、实际、预期和猜测分别写明 |
| 修复后不知道为什么 | 回顾一次改变了什么，保留验证证据 |

## 十二、练习

- [ ] 选择一个真实错误，记录完整命令与错误原文。
- [ ] 为同一个问题构造中文、英文两组检索词。
- [ ] 找到官方教程与 API 参考，说明它们各自作用。
- [ ] 比较两份资料的版本与适用条件。
- [ ] 把一个较大的程序缩小到可运行的最小复现。
- [ ] 完成路径问题案例，用两个工作目录验证。
- [ ] 按模板写一个问题，请同伴在不口头补充的情况下复现。
- [ ] 将解决过程整理为一条 FAQ，保留来源与验证条件。

验收：别人能根据你的记录重现问题，你能说明结论依据，而不只是“某条命令试了以后好了”。

## 十三、方法速查表

| 阶段 | 核心问题 |
|---|---|
| 明确目标 | 我要完成什么？ |
| 保存现象 | 实际发生了什么？ |
| 收集环境 | 哪个系统、版本、目录、输入？ |
| 构造检索词 | 哪些错误和对象名称最有区分度？ |
| 阅读资料 | 前提、参数、返回值、异常是什么？ |
| 验证建议 | 改了什么，结果怎样，能否重复？ |
| 提问 | 对方是否有足够信息接续？ |
| 归档 | 原因、修复、证据和限制是否齐全？ |

## 十四、相关学习资料

- [Python 官方教程](https://docs.python.org/zh-cn/3/tutorial/)：练习从原始文档获取解释与示例。
- [Python pathlib 文档](https://docs.python.org/zh-cn/3/library/pathlib.html)：本文路径案例的参考。
- [Python 官方问题报告说明](https://docs.python.org/3/bugs.html)：了解向成熟项目报告问题的入口和流程，英文。
- [GitHub 创建 Issue](https://docs.github.com/zh/issues/tracking-your-work-with-issues/using-issues/creating-an-issue)：把问题与需求留在项目中。
